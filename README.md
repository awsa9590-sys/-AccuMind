# ميزان | المحاسبة الذكية — نسخة ERP تجريبية

نموذج أولي عربي RTL يعمل داخل المتصفح، مع حفظ محلي عبر `localStorage`. يحتوي الآن على وحدات المحاسبة الأساسية ومركز ERP إضافي مستوحى من مجالات شائعة في أنظمة المؤسسات والمحاسبة السحابية.

## التشغيل

1. فك الضغط عن `mizan_accounting_app.zip`.
2. افتح `index.html` بواسطة Chrome أو Edge.
3. للاستخدام الأفضل شغّل المجلد عبر إضافة Live Server في VS Code؛ بعض المكتبات والموارد الخارجية تتطلب اتصالًا بالإنترنت.

## الملفات

- `index.html`: الواجهة العربية والتنقل.
- `style.css`: الشكل المتجاوب والألوان.
- `app.js`: عمليات التطبيق والحفظ والتقارير والتصدير.

## الوحدات المتاحة

- لوحة قيادة: الإيرادات والمصروفات وصافي الفرق ومخطط يومي ورؤى مبنية على البيانات.
- المعاملات المالية: إضافة وتعديل وحذف وبحث وتصدير CSV.
- المخزون: الأصناف والكميات والتكلفة وحد إعادة الطلب.
- العملاء والموردون: بيانات جهات التعامل وأرصدة مدخلة يدويًا.
- تقارير تشغيلية مبسطة: قائمة الدخل والمركز المالي والتدفقات النقدية، مع الطباعة إلى PDF.
- مساعد محلي بقواعد وكلمات مفتاحية، مع إدخال صوتي إذا دعمه المتصفح.
- OCR: رفع صورة ومحاولة استخراج النص عبر Tesseract.js؛ يجب التأكد يدويًا من كل مبلغ وتاريخ وضريبة.
- **مركز ERP المتقدم:**
  - قيود يومية مزدوجة مبسطة بحساب مدين ودائن بالقيمة نفسها، مع مركز تكلفة ومرجع.
  - فواتير مبيعات ومشتريات بمراحل مسودة واعتماد وترحيل إلى سجل المعاملات.
  - سجل أصول وإهلاك خط مستقيم تقديري وصافي قيمة دفترية تقديري.
  - متابعة مشروعات وأوامر إنتاج بالموازنة والتكلفة الفعلية والانحراف.
  - سجل حركات بنكية ومطابقة يدوية.
  - سجل نشاط محلي وتصدير بيانات ERP إلى JSON.
  - تصدير بيانات الفواتير المرحلة بصيغة JSON لأغراض إعداد التكامل لاحقًا.
- نسخ احتياطي واستعادة JSON تشمل وحدات ERP الإضافية.

## علاقتها بالبرامج الثمانية المذكورة

تجمع النسخة أفكارًا عامة من SAP S/4HANA وOracle ERP وMicrosoft Dynamics 365 وNetSuite وOdoo وSage وQuickBooks ودفترة: إدارة مالية، معاملات، مخزون، عملاء وموردون، فواتير، أصول، مشروعات، رقابة أساسية وتقارير. لا تُنسخ البرامج الأصلية ولا تحل محلها، ولا تحتوي هذه النسخة على تكامل تجاري مباشر معها.

## حدود مهمة قبل الاستخدام التجاري

- هذه نسخة أولية وليست نظامًا معتمدًا لإدارة حسابات شركة فعلية. دفتر القيود الحالي يدعم قيدًا مبسطًا بطرف مدين وطرف دائن؛ لا توجد بعد شجرة حسابات قابلة للتخصيص، أو ميزان مراجعة كامل مرتبط تلقائيًا بجميع المعاملات، أو إقفال فترات.
- لا توجد قاعدة بيانات مركزية أو تسجيل دخول حقيقي أو صلاحيات آمنة أو تعدد شركات/فروع متزامن. حفظ المتصفح غير مناسب كقاعدة بيانات إنتاجية.
- لا يتم حاليًا احتساب تكلفة البضاعة المباعة أو أوامر الإنتاج آليًا من حركات المخزون.
- الإهلاك والمركز المالي والمشروعات حسابات تقديرية تحتاج مراجعة محاسب.
- تصدير الفواتير إلى JSON **ليس** إرسالًا أو اعتمادًا من مصلحة الضرائب المصرية، ولا يجعل التطبيق معتمدًا للفاتورة الإلكترونية. يلزم التكامل الرسمي، والتوقيع/التصديق المطلوب، وإعداد بيانات المنشأة والاختبارات المناسبة قبل الإطلاق.
- التسوية البنكية يدوية وليست اتصالًا مباشرًا بالبنك. والتصدير إلى JSON/CSV ليس تكاملًا حيًا مع Microsoft 365 أو Power BI أو Oracle أو NetSuite أو غيرها.
- المساعد لا يتصل بنموذج ذكاء اصطناعي سحابي؛ يعمل بقواعد محلية بسيطة.
- تعتمد بعض الخصائص على موارد خارجية مثل Google Fonts وFont Awesome وTesseract.js.

## التطوير المطلوب قبل تحويله إلى منتج

خادم وقاعدة بيانات آمنة، تسجيل دخول وصلاحيات حقيقية، دفتر أستاذ/ميزان مراجعة متكامل، دورة مخزون وتكلفة بضاعة مباعة وتصنيع، إدارة رواتب وأصول وسياسات ضريبية قابلة للتهيئة، صلاحيات واعتماد متعدد المستويات، نسخ احتياطي على الخادم، اختبارات محاسبية، وربط رسمي بالأنظمة الخارجية المطلوبة.
